# Stage 6 Technical MVP evidence report

GraphCRUD Stage 6 demonstrates a reproducible, local, containerized Technical MVP and separately records the remaining Pilot-ready packaging evidence. This report does not claim production readiness or corpus-derived accuracy.

Four open-source repositories are pinned by commit and by a fixed analysis subpath. All four bounded runs exited normally and sealed `PARTIAL` snapshots. The partial classification is expected because the corpus harness intentionally does not resolve each repository's complete build classpath; unresolved bindings remain explicit coverage evidence. These runs prove compatibility and non-crashing behavior only. They are never golden facts or an accuracy oracle.

The measured Docker environment has fingerprint `docker-linux-x86_64-7b62ea82b1f32978` (Docker Desktop 29.6.2, 8 CPUs, 7.68 GiB), with GraphCRUD image `sha256:f9040ea692b1d0f3896d02aa04729fa4693d7627aba8816a2696bc54bfe0f604` limited to 2 CPU/2 GiB and Neo4j image `sha256:61715f2b21db10790eaa0cad61470a5c44001907fe2c86ff6deec5997db51edf` limited to 4 CPU/4 GiB. End-to-end samples were 11.418s, 20.567s, 38.170s, and 12.136s. Each run records discovery, parsing, resolution, graph-write, and query timings; the machine-readable values are authoritative. Each sealed snapshot was exported twice with identical semantic SHA-256. A candidate is comparable only under the same derived environment fingerprint; any missing or unexpected stage fails closed, and a common stage regresses when it exceeds its baseline by more than 20%.

The application distribution and both delivery images are reproducible. Two clean distribution builds produced SHA-256 `a6c9197b5c063d54447bfb19faf57055b3dc169c4dd3703d6f45d6fab5918b2e`. Compose uses immutable digests, `pull_policy: never`, read-only source mounts, a non-root GraphCRUD user, a read-only filesystem, bounded resources, persistent graph volumes, health checks, and disabled Neo4j usage reporting. A separate Compose file supports customer-managed graph storage.

SPDX SBOMs and Trivy JSON reports are generated for both images. The vulnerability and Java databases were updated on 2026-08-08. GraphCRUD reported 11 HIGH and 0 CRITICAL findings across six unique CVEs, with no fixed versions. Neo4j 5.26.28 was rejected after the refreshed scan and upgraded to 5.26.29, reducing its result from nine to three HIGH findings. Those remaining Jackson findings have upstream fixes but no published Neo4j 5.26 image containing them. All nine unique findings have explicit owner/reason/expiry records through 2026-08-16; ports are loopback-only, authentication is mandatory, and the supplied client uses Bolt. A fresh scan and vendor-image replacement are mandatory after expiry or as soon as a fixed image is published.

Neo4j Community is distributed as an optional, separate GPLv3 component in an aggregate. The package includes its exact corresponding source ZIP and GPL license. To ensure the separately licensed Aura fleet-management plugin bytes do not survive in an inherited OCI layer, the delivery image is reconstructed `FROM scratch` from a normalized export of the pinned official 5.26.29 Community filesystem after removing only that optional plugin. Every saved-image layer is audited for the plugin path. No Neo4j GPL source or GPL binary is modified. GraphCRUD does not link Neo4j and communicates only over Bolt. Customers can remove or replace it, and GraphCRUD commercial terms do not restrict recipient GPL rights for the GPL component.
